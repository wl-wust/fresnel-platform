# 方法优先测量会话与多帧图像工作流设计

## 目标

重构 PC 端和手机端的数据流程，使其满足：

1. PC/手机所有页签都能正常切换。
2. 同一测量角色可以连续保存多张照片，不覆盖旧照片。
3. 比值法、放大率法和光线追迹法各自只读取对应角色的图像与参数。
4. 图像识别统一输出 `Δx` 等原始量，不生成或覆盖几何追迹量 `d`。
5. 追迹法默认使用 MATLAB 严格追迹结果 `d=0.90213 mm`。
6. PC 与手机端可以通过记录文件交换数据，不混淆测量会话。

## 非目标

- 不改变 `physics.js` 中的物理公式和数值口径。
- 不重新设计不确定度预算和加权合成算法。
- 不在本轮实现跨设备实时同步；跨设备仍通过记录文件导入导出。
- 不为不同方法自动猜测图像角色；用户必须在拍照前选择角色。

## 问题根因

### 页签

`js/pages/pc.js` 与 `js/pages/mobile.js` 的页签同步代码把单元素查询结果当作数组：

```js
BP.ui.$('.tab').forEach(...)
```

单元素没有 `.forEach`，因此切换函数抛错，视觉状态停留在第一页。

修复为：

```js
BP.ui.$$('.tab').forEach(...)
```

手机端同理使用 `BP.ui.$$('.tab-btn')`。

### 单张图片

手机端仅保存一个 `cam.file`，新拍照会覆盖旧照片。改为“测量会话 → 图像角色 → 多帧队列”。

## 数据模型

### 测量会话

```json
{
  "schema": "bp.session/2",
  "id": "session-20261101-200000",
  "method": "ratio",
  "title": "比值法 2026-11-01",
  "created": "2026-11-01T20:00:00+08:00",
  "calibration": {
    "k_mm_px": 0.004,
    "source": "两点标定",
    "L_mm": 5,
    "N_px": 1250
  },
  "params": {},
  "trace": null,
  "roles": {
    "sodium": [],
    "reference": []
  }
}
```

`method` 允许值：

- `basic`：基本公式法
- `ratio`：比值法
- `magnification`：横向放大率法
- `trace`：光线追迹法

### 图像帧

```json
{
  "schema": "bp.frame/1",
  "id": "frame-20261101-200005",
  "sessionId": "session-20261101-200000",
  "role": "sodium",
  "imageKey": "blob-frame-20261101-200005",
  "created": "2026-11-01T20:00:05+08:00",
  "deltaXPx": 163.31,
  "deltaXmm": 0.65324,
  "quality": 0.92,
  "excluded": false,
  "analysis": {
    "axis": "x",
    "visibility": 0.61,
    "periodPxCross": 163.28
  }
}
```

图片 Blob 存 IndexedDB；会话、帧元数据和原始测量量存 IndexedDB。`localStorage` 只保存轻量预设、当前会话 ID 和标定摘要。

## 方法角色

| 方法 | 必需图像角色 | 额外参数 |
|---|---|---|
| 基本公式 | `sodium` | `d、D、k` |
| 比值法 | `sodium、reference` | `lambdaRef、nNa、nRef、D、k` |
| 横向放大率法 | `no_lens、with_lens` | `dPrime、beta、D、k` |
| 光线追迹法 | `sodium` | `trace.d_mm、trace.u_d_mm、D、k` |

角色名称固定，不通过显示文本识别：

- `sodium`：钠光条纹
- `reference`：激光参考条纹
- `no_lens`：无透镜条纹
- `with_lens`：加透镜后条纹
- `calibration`：分划板或标定图

方法页面只允许读取上表中列出的角色。缺少必需角色时显示具体错误，例如：

```text
缺少激光参考条纹，请先在“拍照”页选择“激光参考”角色并采集至少一帧。
```

## 追迹法几何

默认内置 MATLAB 严格追迹预设：

```json
{
  "schema": "bp.trace/1",
  "source": "matlab-strict",
  "label": "MATLAB 严格追迹（报告基准）",
  "d_mm": 0.90213,
  "dParaxial_mm": 0.90199,
  "D_mm": 1000,
  "u_d_mm": null,
  "inputs": {
    "a_mm": 50,
    "A_deg": 1.0,
    "n": 1.5168,
    "t_mm": 0.17,
    "lambda_nm": 589.3
  },
  "traceVersion": "report-table-5.1"
}
```

计算规则：

```text
λ_trace = d_trace × Δx × k / D
```

`d_trace` 不由图片识别产生。`u_d_mm` 缺失时不确定度页显示“未提供”，不能按 0 处理。

`d=0.90213 mm` 只对报告表 5.1 的名义参数成立，不是普适常数。`a`、`A`、`n`、棱镜厚度 `t` 或工作波长改变时，必须重新追迹；其中 `d` 对 `a` 和 `A` 近似线性敏感，不能继续硬编码。

如果当前会话的 `a、A、n、D` 与内置预设不一致，页面显示：

```text
追迹参数已变化，请重新导入 MATLAB 追迹结果，不能继续使用 0.90213 mm。
```

用户可导入新的 `trace.json` 覆盖当前追迹法会话的几何数据。

### 棱镜角测量边界

比值法、追迹法和横向放大率法都是波长解算路径，不是直接的棱镜角测量方法：

- 比值法消去 `A`，不能反求 `A`。
- 追迹法把 `A` 作为输入 `d_trace` 的模型参数，当前实现不输出 `A`。
- 放大率法可由 `d=d′/β` 反算虚光源间距，再在傍轴近似下用 `A≈d/[2a(n−1)]` 间接估计 `A`，但受 `d′、β、a、n` 误差影响。

要精确测得棱镜角，应使用分光计或自准直仪直接测两折射面的夹角。平台后续如需显示 `A`，应明确标记为“分光计输入”或“由追迹反演的等效棱角”，不得与直接测角混为一谈。

## 拍照与识别流程

1. 用户新建测量会话并选择方法。
2. 页面显示该方法需要的角色任务列表。
3. 用户选择一个未完成角色。
4. 打开相机或从相册选择图片。
5. 图片追加到当前角色的帧队列。
6. 识别引擎立即提取 `Δx`、方向、可见度和交叉检查值。
7. 用户可继续拍摄同一角色，或切换到下一个角色。
8. 每个角色显示帧数、`Δx` 均值、标准差、排除帧数和识别质量摘要。
9. 方法页面只在角色任务全部满足后执行计算。

## 页面结构

### PC 端

- 顶部显示“当前测量会话”条：会话名、方法、角色完成度。
- `图像分析` 改为 `测量采集`：支持选择会话、角色、批量导入图片。
- 波长计算页按方法拆成独立卡片，只显示当前方法需要的参数。
- 历史记录页显示会话而不是无归属的孤立结果。

### 手机端

- `拍照` 页增加角色选择器和角色完成度。
- 当前角色下方显示缩略图队列，而不是只显示最后一张图。
- 支持删除单帧、排除单帧、继续添加和重新识别。
- `标定` 页的 `k` 只对当前会话或当前设备生效，来源明确显示。
- `分析` 页先显示角色分组，再显示方法和结果。

## 数据隔离规则

- 所有帧必须带 `sessionId`。
- 所有查询必须同时按 `sessionId` 和 `role` 过滤。
- 方法计算只能使用本会话指定角色的启用帧。
- 追迹法的 `d` 只能来自本会话的 `trace` 字段。
- 比值法不得读取 `no_lens`、`with_lens`。
- 放大率法不得读取 `reference`。
- 导出记录保存原始帧数据、标定、参数和追迹来源，不保存无法追溯的孤立结论。

## 导入导出

`record.json` 升级为包含会话和帧元数据：

```json
{
  "schema": "bp.record/2",
  "session": {},
  "frames": [],
  "trace": null,
  "exportedAt": "2026-11-01T20:10:00+08:00"
}
```

图片默认不放入 `record.json`。手机识别后的 `Δx`、质量值和角色信息足以在 PC 上重新计算。若后续需要跨设备重新识别原图，再增加单独的图像数据包格式。

## 错误处理

- 新照片保存失败：提示 IndexedDB 空间不足或权限问题，不覆盖旧帧。
- 识别失败：帧保留，标记 `analysisError`，允许重新识别。
- 角色不完整：阻止当前方法计算并指出缺失角色。
- 追迹参数不一致：阻止追迹法计算，要求更新追迹数据。
- 导入不同 schema 版本：拒绝导入并提示所需版本。
- 旧 `bp.record/1`：提供迁移路径，导入到“历史兼容会话”。

## 验收标准

1. PC 与手机端所有页签均可切换。
2. 同一角色连续拍 3 张后刷新页面，3 张仍然存在。
3. 比值法页面只显示并读取 `sodium`、`reference` 两组。
4. 放大率法页面只显示并读取 `no_lens`、`with_lens` 两组。
5. 追迹法默认显示 `MATLAB 严格追迹 / d=0.90213 mm`。
6. 修改 `a` 后追迹法提示必须更新 `d_trace`。
7. 导入会话不会覆盖当前会话，会话列表按时间独立显示。
8. 识别结果只写入当前会话和当前角色。
9. 旧 record 迁移后仍能读到原始帧。
10. `tools/selftest.js`、`check-fringe.js`、`check-p1-html.js` 等现有检查继续通过。
