# 手机视频实时采集与最佳帧导入设计

## 目标

在现有菲涅耳双棱镜测量平台中增加视频采集链路：

1. PC 端先选择测量方法和图像角色。
2. PC 生成二维码，手机扫码后直接打开采集页并申请后置摄像头。
3. 手机画面通过 WebRTC 实时传到 PC。
4. PC 按固定间隔分析画面，保留质量最高且不重复的帧。
5. 帧数和主频稳定性都达标时给出声音和页面提示。
6. 用户确认后，把最佳帧写入当前测量会话的当前图像角色。
7. 同一套抽帧与评分逻辑支持导入本地视频。
8. 用户可选择将直播原始视频导出到本机，默认不录制。

## 非目标

- 不实现云端视频存储。
- 不实现多台手机同时推流或多人观看。
- 不录制音频。
- 不实现远程控制手机相机。
- 不在用户确认前自动把候选帧写入测量会话。
- 不保证在无互联网、PeerJS 服务不可达或实验室防火墙阻断时建立直播连接。

## 用户流程

### 直播采集

1. 用户在 PC 端“图像分析”页打开“视频采集”卡片。
2. 用户选择测量方法和当前图像角色。
3. 用户选择目标有效帧数，默认 20，可选 10、20、30。
4. 用户点击“生成扫码连接”，PC 创建 WebRTC 会话并显示二维码。
5. 手机扫码打开 `mobile.html` 的直播采集视图，允许摄像头权限。
6. PC 显示实时画面、连接状态、候选帧数、当前主频和达标状态。
7. PC 每 0.5 秒抽样分析一帧。有效帧进入候选池，候选池只保留高分且时间上不重复的帧。
8. 达到目标帧数且主频变异系数不超过 0.5% 时，PC 给出声音和页面提示。
9. 用户查看候选缩略图和识别参数，可删除个别候选，再点击“加入当前角色”。
10. 写入成功后保留实时预览；用户可停止连接或继续采集新的候选组。

### 原始视频录制

1. 直播面板提供“同时录制原始视频”开关，默认关闭。
2. 开关开启后只录制手机传来的视频轨，不录音频。
3. PC 支持的 Chrome/Edge 优先使用 File System Access API 直接写入用户选择的位置。
4. 不支持直接写文件时使用内存录制，并在开始时提示长视频可能占用大量内存。
5. 录制状态显示时长、当前文件大小和可用导出状态。
6. 直播中断时停止录制并尽量保留已完成部分，允许下载。
7. 导出文件使用 WebM，文件名包含会话、方法、角色和时间。
8. 原始视频不写入测量会话，也不上传服务器。

### 导入视频

1. 用户必须先选择测量方法和图像角色。
2. 用户选择本地视频后，PC 在大约每 0.5 秒对应的时间点抽帧。
3. 抽帧过程显示进度、有效帧数和预计剩余工作，支持取消。
4. 导入流程使用与直播相同的质量评分、去重和达标判断。
5. 视频文件本身已经保存在本机，因此不再重复提供原始视频导出。

切换测量方法、图像角色或活动会话时，清空尚未确认的候选帧和评分状态。

## 连接架构

### 组件

- `video-session`：负责直播状态、PeerJS 配对、WebRTC 媒体流和录制。
- `video-sampler`：负责定时抽帧、质量评分、候选去重和达标判断。
- `video-recorder`：负责 MediaRecorder、文件写入和下载兜底。
- `video-panel`：PC 端交互、二维码、实时预览、候选管理。
- `stream-client`：手机端扫码后的摄像头预览、连接和断线处理。

### WebRTC 与信令

- 使用 PeerJS 公共信令服务建立连接。
- PC 和手机页面仍由 GitHub Pages 提供，不需要安装软件。
- 视频媒体通过 WebRTC 点对点传输，不经过 PeerJS 转发。
- PC 生成高强度随机房间标识和连接 token，二维码仅包含本次连接所需参数。
- 手机拨号时在调用元数据中携带 token；PC 在接听前校验 token。
- token 不匹配、重复连接或连接超时都必须被拒绝并显示原因。
- 手机离开页面、主动停止、直播轨结束或网络断开时，释放摄像头并通知 PC。

## 抽帧与质量评分

### 采样

- 直播每 0.5 秒分析一次，不处理每一帧。
- 分析使用缩小后的工作图，降低主线程压力；最终保存的候选帧使用原始视频分辨率。
- 分析结果的像素周期必须换算回视频原始坐标，避免缩放改变 `k` 的口径。
- 同一个候选在时间上至少间隔 0.5 秒，避免把连续近似帧当成多帧数据。

### 有效帧

候选帧必须同时满足：

- 现有条纹识别成功。
- 条纹可见度不低于 3%。
- 频谱信噪比不低于 6。
- 自相关峰值不低于 0.2。
- 主频周期与零交叉周期的相对差不超过 2%。
- 接近饱和的像素比例不超过 2%。

任一条不满足时，不写入候选池，但在实时状态区显示最主要原因。

### 质量分数

候选分数综合以下指标并归一化到 0 到 1：

- 条纹可见度：35%。
- 频谱信噪比：25%。
- 自相关峰值：20%。
- 两种周期算法一致性：10%。
- 过曝比例：10%。

候选池按分数降序维护，不得超过目标帧数的三倍。

### 数据足够

同时满足以下条件才提示数据足够：

- 有效候选帧数达到用户选择的目标帧数。
- 所有候选帧主频的变异系数不超过 0.5%。
- 分数最高的目标帧数中不存在明显过曝帧。

不达标时，状态区持续显示例如“已有 16/20 帧”“主频波动 0.8%”或“过曝帧较多，请降低曝光”。

## 会话数据

现有 `bp.session/2` 和 `bp.frame/1` 保持兼容。帧记录增加可选字段：

- `source`: `live` 或 `video`。
- `sourceName`: 导入视频文件名或直播房间摘要。
- `capturedAt`: 原视频时间或直播抽帧时间。
- `qualityScore`: 0 到 1 的综合分数。
- `selection`: 抽帧阈值、目标数和评分摘要。

最佳帧以 JPEG Blob 写入现有 IndexedDB，并继续通过 `BP.sessions.addFrame()` 归属到当前会话和角色。

## 页面与状态

### PC

“图像分析”页新增以下状态：

- 未配置：尚未选择方法或角色。
- 等待扫码。
- 正在连接。
- 实时采集中。
- 数据足够。
- 导入视频分析中。
- 已写入会话。
- 连接失败或设备断线。

候选项显示缩略图、时间、条纹周期、可见度、频谱信噪比和综合分数。

### 手机

直播页只保留必要内容：

- 摄像头预览。
- 连接状态。
- 当前分辨率。
- 停止按钮。
- 错误提示。

扫码链接无效、token 错误、摄像头被拒绝或 PeerJS 连接失败时，手机端显示可操作的错误说明。

## 错误处理

- 摄像头权限被拒绝：提示检查浏览器权限和 HTTPS。
- 扫码过期：PC 可重新生成二维码。
- PeerJS 服务不可达：提示网络限制，并引导使用“导入视频”。
- 直播中断：停止录制、保留候选、释放摄像头并允许导出已录内容。
- 视频编码不受支持：禁用原始视频导出，但不影响最佳帧采集。
- 内存录制空间风险：显示警告；达到内部安全上限时自动停止并导出。
- 导入视频编码不受支持或时长过短：显示可恢复错误。
- 页面刷新：清空未确认候选，已经写入会话的帧继续保留。

## 隐私与安全

- 原始视频和最佳帧默认只保存在浏览器本机。
- 直播不自动上传视频。
- 原始视频录制默认关闭。
- 房间 token 使用加密安全随机数生成。
- PC 只接受当前二维码对应 token 的媒体连接。

## 测试

### 自动测试

- 有效帧门限的边界测试。
- 质量分数单调性测试。
- 候选去重和时间间隔测试。
- 目标帧数与主频变异系数达标测试。
- 方法、角色和活动会话切换时的候选清理测试。
- 帧可选字段写入和读取测试。
- 原始视频文件名、浏览器能力检测和降级路径测试。
- HTML ID、脚本版本、全局绑定和发布文件一致性检查。

### 浏览器实测

- PC Chrome/Edge 与手机 Chrome。
- PC Chrome/Edge 与手机 Safari。
- 摄像头拒绝、扫码失败、断网、主动停止和重复连接。
- 直播最佳帧写入会话后，在 PC 历史记录中重新计算。
- 本地 WebM/MP4 导入抽帧。
- 原始视频开关关闭和开启两条路径。

### 验收标准

- 手机扫码后无需安装应用即可看到实时画面。
- PC 能自动排除低质量帧并保留目标数量的最佳帧。
- 达到目标且主频稳定时给出明确提示。
- 用户确认后帧正确进入所选会话和角色，不与其他角色混用。
- 导入视频复用同一评分与达标逻辑。
- 原始视频可选录制并在支持的 PC 浏览器导出。
- 现有条纹识别、会话、标定、发布和版本检查全部通过。
