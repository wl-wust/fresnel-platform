# 光学平台工程线稿与交互增强设计

日期：2026-11-04  
页面：`optical.html`  
状态：设计已确认，待规格审阅

## 1. 背景

当前光学页能按真实台面距离计算双棱镜虚光源间距和条纹间距，但仪器仍是彩色矩形与 emoji，光路只有少量直线和虚线，顶角只能在数字框里修改，拖动元件时也没有水平约束。用户希望参考技术制图中的双棱镜实验图，把页面改成更容易理解和演示的工程线稿，并补充光源切换、光传播效果、可调顶角与水平校准。

参考图位于 `D:/DSH/test/_fig31_check.png`。本次采用浏览器伴游中用户选定的 A 方案“精密工程线稿”。

## 2. 目标

1. 用工程线稿语言重绘导轨、光源、单缝、双棱镜、透镜和观察屏。
2. 把光路从单根线升级为可见的传播光锥、亮边、流动光点和虚光源路径。
3. 支持钠灯与激光两种光源，钠灯默认 `589.3 nm`，激光默认 `650 nm`。
4. 增加 `0.2°–2.0°` 的棱镜顶角滑杆，并与现有数字输入双向同步。
5. 增加“水平校准”复选框；开启后拖动只改变水平位置。
6. 保留现有物理计算、真实毫米标尺、条纹计算、DPR 清晰度和触摸拖动。

## 3. 非目标

- 不改变现有双棱镜、透镜和条纹计算公式。
- 不重写整个光学模拟器，不引入新的前端框架或 Canvas 依赖。
- 不让光源切换改变实验方法、识别参数或结果页面。
- 不把参考图直接作为背景图片；仪器必须由 Canvas 矢量绘制。
- 不自动把未对齐仪器吸附到光轴；“水平对齐”按钮继续负责吸附。

## 4. 视觉方向

### 4.1 整体语言

- 背景使用接近白纸的暖白色，叠加低对比度工程网格。
- 仪器使用深墨色粗轮廓、浅色填充和少量阴影，不使用 emoji 作为主体。
- 元件采用圆形编号或带引线的短标签，编号与名称同时可辨。
- 导轨使用双层轮廓、毫米刻度和双向尺寸箭头。
- 选中状态使用清晰的强调色描边，不覆盖仪器内部细节。

### 4.2 光源表现

- 钠灯：宽幅黄色半透明光锥、柔和亮边和黄色流动光点。
- 激光：更窄的红色光束、集中的亮芯和红色流动光点。
- 棱镜后显示分束光锥和虚光源 `S₁`、`S₂`；虚光路使用虚线。
- 干涉重叠区采用轻量斜线或网点阴影，与普通光路区分。
- “显示光路”关闭后，光锥、光点和动画全部停止；“显示标签”只控制文字标签。

### 4.3 顶角示意

真实顶角只有约 `1°`，按真实比例绘制时视觉变化过小。画布中的棱镜楔角允许按教学示意图放大，但参数标签和计算结果始终使用真实顶角。页面原有“傍轴近似”提示保留，并补一句“画布棱镜角为示意放大”。

## 5. 架构

### 5.1 新增模块

新增 `js/pages/optical-visual.js`，在 `optical-rail.js` 之后加载。模块负责：

- 工程线稿风格的导轨、仪器、编号和光路绘制。
- 钠灯/激光视觉样式和传播动画。
- 顶角滑杆与数字输入同步。
- 为水平锁提供只读状态接口。
- 对外暴露测试需要的纯函数与运行时状态。

模块继续使用现有全局 `devices`、`CONFIG`、`showLight`、`showLabels` 和 `render()`，不创建第二份物理状态。

### 5.2 需要修改的现有文件

- `optical.html`：加入光源选择、顶角滑杆、水平校准复选框和新脚本引用。
- `css/optical_v2.css`：补充新控件、工程线稿画布背景和参数提示样式。
- `css/optical-responsive.css`：保证新控件在手机宽度下不溢出、不裁切。
- `js/pages/optical-dpr.js`：拖动时读取水平锁状态；锁定时只更新 `x`。
- `js/pages/optical-rail.js`：仅补充必要的视觉刷新和参数变化通知，不复制计算逻辑。

### 5.3 绘制顺序

每帧按以下顺序绘制：

1. 暖白背景与工程网格。
2. 毫米导轨、刻度和尺寸标注。
3. 光轴、传播光锥、亮边、虚光路和干涉区。
4. 光源与各光学元件。
5. 编号、引线、选中框和拖动反馈。

光路位于仪器下方，避免半透明光锥盖住元件轮廓。

## 6. 状态与数据流

### 6.1 光源切换

- 新增 `#sourceMode`，选项为 `sodium` 与 `laser`，默认 `sodium`。
- 切换到钠灯时把 `#lambda` 更新为 `589.3`；切换到激光时更新为 `650`。
- 波长更新后触发现有 `change` 事件，由 `optical-rail.js` 重算并重绘条纹。
- 光源模式只由下拉框切换；用户手动编辑波长不会自动改变光源模式。
- 光源样式只影响颜色、光束宽度、标签与默认波长，不影响计算方法。

### 6.2 顶角调节

- `#beta` 继续作为唯一真实顶角数据源。
- 新增 `#betaRange`，范围为 `0.2–2.0`，步长 `0.01`，默认 `1.0`。
- 滑杆和数字框任一方变化时同步另一方，并触发现有 `change` 流程。
- 棱镜画布几何由真实顶角映射到放大的示意图角度；`d` 与 `Δx` 始终用真实顶角计算。

### 6.3 水平校准

- 新增 `#horizontalLock` 复选框，默认关闭。
- 开启时，拖动开始后冻结元件当前的 `y`，只按指针更新 `x`，仍受画布左右边界限制。
- 关闭时恢复现有的 `x/y` 自由拖动。
- 开启水平锁不会自动对齐；用户仍可使用“水平对齐”按钮把所有仪器吸附到光轴。

### 6.4 光路动画

- 使用单个 `requestAnimationFrame` 循环。
- 每帧只读取设备位置和样式状态，不调用 `updateParams()` 或 `simulateInterference()`。
- `showLight=false`、页面不可见、画布不可用或动画已停止时不再排下一帧。
- 重新开启光路时只启动一个循环；重复启动必须先取消旧循环。
- 页面设置 `prefers-reduced-motion: reduce` 时保留静态光锥和亮边，不绘制移动光点。

## 7. 异常与边界处理

- 顶角输入为空、非数字或超出范围时，限制到最近的有效边界；空值恢复上一次有效值。
- 缺少光源、单缝、棱镜或屏幕时，只绘制已有元件，并跳过依赖缺失元件的光路段。
- 画布、控件或 2D Context 不存在时，模块安全退出，不阻断现有页面脚本。
- DPR 变化后重新设置 Canvas 后备存储，绘制坐标继续使用 CSS 像素。
- 动画循环启动、停止和页面可见性切换必须幂等，不能累积多个 RAF。
- 手机窄屏中参数控件允许换行，但不得产生横向滚动或文字裁切。

## 8. 测试与验收

### 8.1 自动检查

- 顶角从 `1.0°` 改到其他值后，棱镜示意几何、虚光源间距 `d` 和条纹间距 `Δx` 同步变化。
- 切换到激光后，波长自动变为 `650 nm`，光束样式变为红色窄束；切回钠灯恢复 `589.3 nm` 与黄色宽束。
- 水平锁开启后模拟拖动，元件 `x` 改变而 `y` 保持不变；关闭后 `x/y` 都能改变。
- 光路开启时动画处于运行状态，关闭后 RAF 不再继续排队。
- `prefers-reduced-motion` 模式下仍能绘制静态光路。
- 原有 `check-optical-geometry.js`、`check-optical-numbers.js`、`check-pages.js`、`check-versions.js` 和 `browser-check.py` 全部通过。

### 8.2 浏览器验收

- PC `1440×1000` 与手机 `390×844` 均显示完整画布和控件。
- 页面无横向溢出，按钮和标签不裁切，控制台无错误。
- 画布非空，工程线稿仪器、光锥、编号和标尺均可见。
- 关闭光路后光束消失且无残留动画；再次打开只恢复一个动画循环。
- 改顶角、切换光源、拖动锁定仪器后，结果区与条纹图及时刷新。

## 9. 交付标准

- 采用 A 方案工程线稿，仪器不再以 emoji 和纯色矩形为主体。
- 光路具备清楚的传播感和动画，不只是单根细线。
- 钠灯/激光切换、顶角滑杆、水平校准三项交互完整可用。
- 现有计算口径、真实毫米映射、PC/手机响应式与已知回归测试不退化。
- 版本缓存按项目现有 `stamp-version.js` 流程统一刷新。
