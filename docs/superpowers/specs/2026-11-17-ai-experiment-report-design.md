# 菲涅耳双棱镜 AI 实验数据报告设计

## 目标

在现有纯前端菲涅耳双棱镜实验平台中新增独立、论文级、可轻微交互的
AI 实验数据报告页。报告使用两次真实实验目录中的会话、图片和视频结果，
比较比值法、光线追迹法、横向放大率法，并清楚区分实测、报告预设、模型追迹、
仅参考和缺失数据。

同时完成两项配套能力：

1. 报告页可以导入平台生成的 `bp.record/2` 和新版 `bp.report/1` 数据包。
2. 从真实实验图片中自动评分、人工复核并整理一套报告精选图片，保留原图不变。

## 已确认口径

- 三个重点方法：比值法、光线追迹法、横向放大率法。
- 基本公式作为共同基础和误差基线，不作为第四条正式对比路径。
- 优先使用真实识别值；缺失参数允许采用报告预设，但必须显示“条件计算”。
- 红光短片只有 5 个参考帧，始终标记 `referenceOnly=true`，不得作为正式钠光实验数据。
- 旧报告表 5.2 的 `0.10% / 0.14% / 0.13%` 只作为历史仿真基准，不改写为本次实测不确定度。
- 所有数据导入、计算和导出均在浏览器本地完成，不上传服务器。
- 项目文件只写入 D 盘。

## 系统结构

新增独立报告页 `report.html`，复用现有 `js/physics.js`、`js/core/*` 和
`js/pages/pc-video.js` 已产生的数据。报告页不嵌入 PC 测量页签，避免加重现有
采集中枢。

建议新增模块：

- `js/core/report-data.js`：报告数据模型、导入校验、来源合并和派生指标。
- `js/core/report-errors.js`：误差传播、条件计算、准确度与一致性检验。
- `js/pages/report.js`：报告页渲染和交互。
- `css/report.css`：报告桌面/手机布局、图表和打印样式。
- `report.html`：报告入口。
- `tools/check-report-data.js`：纯数据与误差测试。
- `tools/check-report-browser.py`：PC/手机 Playwright 测试。

PC 与手机首页增加“AI 数据报告”入口。报告页在桌面端使用固定左侧目录和主内容
双栏；手机端改为单栏、顶部横向胶囊导航。

## 数据模型

报告使用统一的内存结构 `ReportDataset`：

```text
ReportDataset
  meta
    title, generatedAt, source, experimentDate
  sessions[]
    id, method, params, calibration, frames, roleStats
  methods
    ratio, trace, magnification
  rayTrace
    points[], paraxial[], exact[], residuals[]
  images[]
    sourcePath, reportPath, category, metrics, caption
  provenance[]
    field, value, sourceType, sourceDetail
  warnings[]
```

`sourceType` 只允许以下值：

- `measured`：当前会话真实识别。
- `reportPreset`：旧报告中的预设或基准。
- `modelTrace`：精确光线追迹模型。
- `manual`：用户手动输入。
- `referenceOnly`：红光等仅参考数据。
- `missing`：缺失，不得用零代替。

## 输入格式

### `bp.record/2`

直接兼容现有平台导出格式，读取：

- 会话、方法、参数和参数来源。
- 图像角色及多帧真实 `Δx`、条纹数、质量门限和稳定性。
- 像素标定 `k`、`L`、`N` 及来源。
- 视频/照片来源、目标帧数和 `referenceOnly`。

### `bp.report/1`

新增报告数据快照，用于保存已导入会话、条件计算选择和图片清单。至少包含：

```json
{
  "version": "bp.report/1",
  "generatedAt": "ISO-8601",
  "dataset": {},
  "methodSettings": {},
  "imageManifest": []
}
```

导入流程必须为“选择文件 → 本地解析 → 预览摘要 → 用户确认 → 更新报告”。无效
JSON、版本不兼容、角色不匹配和缺少必需字段必须指出具体错误；不得静默归零或
自动替换为报告预设。

## 三方法计算与误差

### 比值法

使用钠光与激光参考两组角色的多帧 `Δx`。参考波长和折射率若来自报告预设，
结果标记为“条件计算”。比值法可消去 `d、D、k`，重点展示双波长比例和色散修正。

### 光线追迹法

展示傍轴公式 `d_par = 2a(n-1)A` 与精确追迹 `d_trace(a)`，给出每个 `a` 的
`d_trace`、`d_par` 和相对残差。交互图支持悬停读数、隐藏傍轴曲线和切换残差视图。
内置 `d_trace=0.90213 mm` 只适用于报告的标称参数，必须标记“模型追迹”，
参数变化时提示重新追迹。

### 横向放大率法

通过 `d = d'/beta` 或 `d = sqrt(d1' * d2')` 反算虚光源间距。缺少无透镜/加透镜
角色或 `d'、beta` 时显示缺失，不生成伪结果；采用报告预设时显示条件误差。

### 三层误差

报告分别展示，不把不同性质的误差合成为单一“精度”：

1. 实测离散性：多帧均值、标准差、均值标准误差、变异系数和有效帧数。
2. 条件误差：按报告误差传播式计算；每个输入均有来源标签。
3. 准确度与一致性：相对 589.3 nm 的偏差、三方法差异和 `chi^2` 检验。

基本公式结果只作为误差基线和公式校核，不进入三路径最优合成。

## 报告页面

页面区域：

1. 结论摘要：最优条件估计、相对偏差、数据可信完成度和关键警告。
2. 三方法对比：公式、输入来源、结果、误差、适用边界。
3. 误差归因：可点击误差瀑布图，展开来源与传播公式。
4. 光线追迹：与用户提供的 `d-a` 图一致的交互曲线和残差。
5. 数据审计：按来源类型筛选所有关键字段。
6. 图片精选：分类图片墙、评分、建议图注和原路径。

视觉使用深海蓝灰底色；暖金色表示追迹，青绿色表示实测，蓝色表示预设。
状态同时使用文字标签，不只依赖颜色。交互保持克制，不加入自动滚动动画或无意义动效。

报告支持：

- 导入 `bp.record/2` 或 `bp.report/1`。
- 导出 `bp.report/1` JSON 快照。
- 打印/另存为 PDF；固定图表尺寸、分页和背景打印。

## 图片精选

自动评分指标：

- 清晰度：拉普拉斯方差。
- 曝光：过曝/欠曝像素比例。
- 对比度：灰度分布与局部对比。
- 条纹质量：可见度、周期有效性、方向稳定性。
- 重复度：近似去重，避免同一场景重复入报告。

分类：

- `apparatus`：装置全景和关键部件。
- `sodium_fringe`：最佳钠光条纹。
- `reference_fringe`：最佳激光参考条纹。
- `second_image`：二次成像放大像/缩小像。
- `reticle`：分划板刻线。
- `other_data`：其他有用原始数据。

输出规则：

- 不移动、不覆盖、不删除原始实验图片。
- 规范精选目录：`D:\物理实验\第二次自主设计\报告精选图片`。
- 文件名使用“类别-用途-序号”的可读名称。
- 生成 `manifest.json`，记录原路径、精选副本、类别、评分、图注和 SHA256。
- 平台内生成优化压缩副本，保证本地局域网和 GitHub Pages 可加载。

## 错误处理

- 空会话、无有效帧或缺角色：报告仍可打开，但对应方法显示“不可计算”。
- 导入格式错误：显示字段级错误和修复建议。
- 页面刷新：已确认的本地报告数据从 IndexedDB/localStorage 恢复。
- 视频/图片资源缺失：保留数值和来源路径，显示占位说明。
- 打印时隐藏交互控件，保留图、表、来源标签和警告。

## 测试

### 数据测试

- 三方法结果和误差传播的已知样例。
- 同一输入重复加载结果一致。
- 缺失角色不被零填充。
- 报告预设与实测来源不混淆。
- `bp.record/2` 与 `bp.report/1` 往返导入。

### 浏览器测试

- PC/手机报告页无脚本和资源错误。
- 数据导入、错误提示、确认更新流程。
- 悬停、曲线显隐、残差切换和审计筛选。
- 手机端无横向溢出，图片墙可正常查看。
- 打印媒体模拟下分页和控件隐藏正确。

### 回归测试

- 现有 Node/PowerShell 语法检查。
- 页面接线、条纹识别、会话、视频采样、局域网信令与现有部署检查。

## 非目标

- 不在本功能中重新训练或调用云端大模型。
- 不把仿真结果描述成真实测量。
- 不实现后端账号、云存储或多人协作。
- 不自动发布 GitHub Pages；发布仍需用户明确确认。

## 验收标准

- 平台内可打开独立报告页，桌面和手机布局正常。
- 三种方法均有作用说明、来源、结果或缺失原因。
- 可交互查看光线追迹曲线及残差。
- 可导入至少一个真实 `bp.record/2` 并生成报告。
- 可导出并重新导入 `bp.report/1`，结果一致。
- 精选图片集中至少包含装置、条纹、刻线等报告可用类别，原图不变。
- 全量自动化测试通过，且没有把预设、参考或仿真值伪装成实测。
